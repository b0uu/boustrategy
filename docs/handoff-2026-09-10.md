## Host facts that are easy to get wrong

- **Tasks must run in the interactive session with RunLevel Highest.** Under a password or
  batch logon, Codex's Windows sandbox runner times out connecting its runner pipe and the
  agent does nothing. Keep the server signed in; disconnect RDP rather than signing out.
- **Codex is the only agent.** A dedicated identity lives at `C:\Users\Administrator\.codex-boustrategy`
  (`CODEX_HOME`), currently logged in with the maintainer's main ChatGPT account until a
  second account exists. Models come from the gitignored `ops/digester.local.psd1`:
  `gpt-5.6-luna` for digests and broker reads, `gpt-5.6-sol` for reviews and execution.
- **Inside the Codex sandbox, Windows TLS has no credentials.** `curl.exe` and
  `Invoke-WebRequest` fail with `SEC_E_NO_CREDENTIALS`; Python `httpx` works. Media is
  downloaded by `python -m app.x.run media --run <run_id>`.
- **The Robinhood grant exposes several accounts**, including the maintainer's personal
  margin account. Only the Agentic account's fingerprint (kept in the gitignored
  `ops/live.local.json`) is bound and enabled. Prompts and
  `docs/execution/EXECUTOR.md` require fingerprint selection before any broker call.
- **The authoring session has web search but no shell and no filesystem.** All eight strategy
  and prompt documents are inlined into the intake by `assemble_intake`.

## Design pass against the mock, 2026-09-10

The mock is `BouStrategy Handoff Spec (1).html` in the maintainer's Downloads, a design-canvas
bundle: its markup is not in the file body but JSON-encoded inside the
`<script type="__bundler/template">` tag, so extract that before reading it. Two screens, the
dashboard and the decision trace. The tokens, type rhythm and most layouts already matched,
so everything below is a structural delta rather than a restyle. Nothing here changed what is
published, only what the page shows of it.

- **Stylesheet consolidated.** `styles.css` had grown four append-only override blocks. Three
  competing `.stream-row` column definitions, a second `.policy-row` rule that added a
  `border-bottom` on top of the existing `border-top` and doubled every hairline, and a dead
  561–600px band that gave the four-child feed row three columns and wrapped its chevron. Dead
  selectors for removed features (`.scope-controls`, `.feed-content`, `.loading-line`,
  `.mode-note`, `.latest-decision`, `.agent-status-line`, `.activity`) are gone. Every
  surviving declaration is the one that was already winning, so the rendered result is
  unchanged except for the doubled hairline and the 561–600px wrap.
- **Policy rows carry their identity and description in the closed row**, as in the mock's
  `code | name + description | kind` anatomy. Our `rule_id` is long snake_case rather than the
  mock's `R-04`, so the id trails the name instead of taking its own 68px column.
- **Policy checks read as one marked table** — mark, rule, observed, threshold, with a header
  row — instead of fourteen collapsed disclosures. A check the gate never reached
  (`not_applicable`, `missing_input`) takes no verdict colour: it is not a pass and not a
  failure. Detail stays behind the row.
- **A boolean threshold now reads "Required"**, not "Yes". `thresholdValue` wraps `ruleValue`
  for the threshold slots only; an observed boolean is still Yes/No.
- **Section order follows the mock**: sizing directly under the stages that produced it, then
  trigger, sources, source pack, invalidation, tags.
- **New on the trace page**: a Source pack listing every published source once (this also
  replaced a bare orphan-source tail that rendered inside the claims section), Invalidation
  criteria as a first-class section rather than one quarter of a disclosure, a Strategy &
  themes tag row (`.tags` had been styled but never used), and six identifiers in the head
  including which review authored the record.
- **Stage rows have the mock's right-hand clock.** `PublicStage.started_at` / `completed_at`
  are optional authored fields that nothing populates yet, so the column is empty today and
  fills in on its own if authoring starts recording them.
- **The live browser fixture carries a real review.** `generate.py` grew a `live_run` helper,
  because `save_run` refuses a `mode="live"` run without a prepared `ReasoningRun` and a
  `LivePortfolioSnapshot` whose fingerprint matches the account. The merged-stream test no
  longer copies paper activity over the live scope to have something to render.
- **Four browser tests were added** for the marked check table, the closed policy row, the
  source pack and the promoted invalidation criteria.

Not adopted from the mock, beyond the two doctrine items above: its metric row leads with AUM
and a policy-pass rate, where this dashboard leads with portfolio value, range return and
reviews today. The mock also shows a per-position **cost basis** that the published position
payload does not carry.
